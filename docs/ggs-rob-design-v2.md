## 1. 基本思想と運用方針

### 1.1 ポータブル・アルファ
コア資産（東証上場ETF、3,000万円超）の長期複利成長を維持しつつ、代用有価証券として眠っている担保余力から信用取引で追加収益を得る。コア資産は売らない。コア資産を守ることが、収益より優先する。

### 1.2 「予測」の排除と「適応・執行」への集中
将来の価格は予測しない。現在の市場構造（ボラティリティの持続性、時間軸ごとのモメンタム／平均回帰特性）に合わせて「稼働させる戦略」と「ポジションサイズ」を切り替え、規律どおりに執行する。パラメータの定期更新は「直近の構造が続く」という弱い仮定に立つことを自覚し、更新幅と頻度を抑える（§6.3）。

### 1.3 リスク予算（本設計の成立条件）
ポータブル・アルファの最大の脅威は、**担保（海外株ETF）・建玉（日本株）・為替（円高）が同時に悪化する**リスクオフ局面で維持率が急低下し、追証→担保ETFの強制決済に至ることである。以下を設計の前提条件とする。

| 項目 | 規定 |
|---|---|
| 掛目 | 証券会社規約の値（通常80%）を用いるが、**証券会社が任意に引き下げられる条項**があることを前提に、ストレステストでは70%で計算する |
| ストレステスト | 2008/9–10月、2011/3月、2015/8月、2018/2月、2020/3月、2024/8/5 の各局面について「担保評価額×掛目 − 建玉評価損 − 金利諸費用」で維持率の日次推移を再現する。為替は同期間の実績ドル円を用いる |
| 合算レバレッジ上限 | スイング＋デイトレの建玉合計は、**ストレス後の担保評価額**（上記最悪ケース）を基準に、維持率が警戒水準を割らない範囲で決める。「保証金の0.5〜0.7倍」という目安はこの計算で置き換える |
| 現金バッファ | 総資金の15〜20%（450万〜600万円）を**担保計算に含めない現金**として別建てで維持する。決済損、金利・貸株料、追証の初動対応に使う |
| 維持率トリガー | 3段階。例: 警戒（新規停止）／縮小（建玉を半減）／全決済。具体値はストレステスト後に確定し、設定テーブルで管理する |
| 相関クラスタ | 日経・TOPIX・S&P500・NASDAQ等の株式指数ETFは、急落時に相関が1に近づくため**1つのリスク単位**として合算管理する |
| 誤発注防止 | 担保ETFの売却・現引・現渡を、発注モジュールの最下層でブラックリスト（コード側ハードコード＋設定テーブルの二重化）により拒否する |
| オーバーナイト | デイトレ枠は15:24までに完全クローズ。夜間リスクはスイング枠に限定する |

## 2. システムアーキテクチャ

### 2.1 インフラ・実行環境
- 実行環境: Windows 11 Pro + Python 3.11。本番PCは24時間稼働、1日1回定時再起動（§8.1）
- 開発環境: 開発PC（Windows 11）+ Claude Code / Antigravity CLI。kabuステーションは本番PCで常駐、開発PCでは検証時のみ手動起動
- ジョブ管理: PowerShell + タスクスケジューラ + DB上のジョブ管理テーブル（リリース制御、起動時刻、死活監視、実行結果）
- データベース: PostgreSQL 18（ローカル）
  - `bb`: 共通系（銘柄マスタ、取引カレンダー、SQ・限月カレンダー、共通市場データ）
  - `rr`: `rob`専用（レジーム履歴、シグナル、約定ログ、パラメータ履歴、板・歩み値・分足）
  - 板・歩み値は増加が速いため月次パーティションとし、保持期間と集約方針（分足への縮約）を決める
- データソース
  - **本番の日次データ**: J-Quants等の正規ソース、または証券会社提供データ。先物出来高は限月交代を調整する
  - **yfinance は研究用途に限定**する（非公式API、レート制限、遡及修正があり、本番の判定入力には使わない）
  - 場中データ: kabuステーションAPI（PUSH配信。登録銘柄数上限とAPIレート制限は規約で確認する）
- AI・LLM
  - ローカルLLM（Ollama）: 朝のニュース・経済カレンダーの構造化、週末の運用ログ初期集計
  - 外部LLM（Gemini）: 敗因分析、パラメータ劣化・過学習の監査レポート
  - **LLM出力は発注に直結させない**。許可するのは「ロット係数の上限を下げる」「人間向け警告」のみ。出力はスキーマ検証を通す

## 3. 階層①：環境認識（日足レジーム判定）

### 3.1 4区分の定義
日足のみ、先読みなしで判定する。

- **方向軸**: 終値と200日移動平均線。±2%のヒステリシス帯でチャタリングを抑制
- **ボラ軸**: Yang-Zhang 20日ボラ（$\sigma_{YZ,20}$）の過去3年パーセンタイル順位、**または**年率絶対値の閾値（OR条件、§3.2-3）

| 区分 | 定義 | 基本スタンス |
|---|---|---|
| A 上昇・平穏 | 200日線超 × 低〜中ボラ | 順張り候補（検証後）。逆張りは利幅が出ないため停止 |
| B 上昇・荒れ | 200日線超 × 高ボラ | 逆張りを主軸に、順張りはやや縮小ロット |
| C 下降・荒れ | 200日線割れ × 高ボラ | **逆張り特化**。順張り買いは禁止 |
| D 下降・平穏 | 200日線割れ × 低〜中ボラ | **停止**。長期データで有効性が示されるまで例外を認めない |

### 3.2 ボラ軸の仕様
1. **Yang-Zhang推定量（即時導入）**: 終値ベースは日中の乱高下を、Parkinsonは寄り付きギャップを取り逃す。東証ETFのボラの大半はオーバーナイトで生じるため、ギャップ項と日中項を統合したYang-Zhangを採用する。
2. **ATR比による先行検知（検証後導入）**: $\mathrm{ATR}_5 / \mathrm{ATR}_{20}$（または $\sigma_{YZ,5}/\sigma_{YZ,20}$）が閾値を**2営業日連続**で超えたら早期にB/Cへ遷移、下回ったらA/Dへ早期復帰。1日のスパイクで反応させない。
3. **絶対値キャップ**: 2024年8月のような極端値が3年窓に残る間（2027年夏頃まで）、上位20%の閾値が高止まりする。年率ボラの絶対水準（例: 25%以上は無条件で「荒れ」、12%以下は無条件で「平穏」）をOR条件で併用する。
4. **ボラ軸のヒステリシス**: 「荒れ」への遷移は上位20%（80パーセンタイル）、「平穏」への復帰は60パーセンタイルを割った時点とする。方向軸だけでなくボラ軸にも二閾値を設け、年14〜20回の切替を抑える。
5. **出来高**: ETF自体の出来高は設定・解約、NISAフロー、レバETFのリバランスで歪むため**判定には使わない**。遷移確認フィルタを試す場合は、ロール調整済み先物出来高または東証プライム売買代金を用いる。

### 3.3 複数指数の扱いとグローバル・オーバーライド
- レジームは**指数ごと**に判定する（1321→日経、1306→TOPIX、1547/2558→S&P500、1545→NASDAQ）。デイトレ（1570）は日経のレジームに従う。
- 円建て海外ETFは為替トレンドが200日線の判定に混入する。判定は**原指数**（`^GSPC`, `^NDX`）で行い、ETFは執行対象としてのみ扱う。
- **グローバル・リスクオフ・オーバーライド**: 主要指数（日経・S&P500）のいずれかがCまたはDに入った場合、全指数のリスク枠を一段縮小する。急落時の相関上昇に対する防御であり、個別判定より優先する。

### 3.4 レジームの出力
`rob regime` は日次で以下を `rr` に書き出す: 指数ごとの区分、遷移の有無、ボラ水準（パーセンタイルと絶対値）、ATR比、当日のリスク枠（ロット係数）、稼働戦略フラグ、オーバーライドの有無。下流はこのテーブルだけを読む。

## 4. 階層②：スイングトレード（日足）

### 4.1 対象と制約
- ユニバース: 1321、1306、1547/2558、1545。他に先進国株式ETF等を検討。1570はスイングに**使わない**（レバETFの減価）。
- 全銘柄を1つの相関クラスタとして合算管理。同時ポジション数と合算建玉はリスク予算（§1.3）の範囲内。
- **ナンピン禁止**: 同クラスタに含み損のポジションがある間は新規エントリー不可（コードで強制）。
- 制度信用の6ヶ月期日より十分短い保有期間とする。一般信用（無期限）は金利差を比較して選択。

### 4.2 売買ルール（優先順位つき）
| 優先 | レジーム | 戦略 | 根拠と位置づけ |
|---|---|---|---|
| 1 | B / C | 逆張り（例: 5日安値更新後の反発確認でエントリー） | 日足検証でコスト控除前+132〜247bp/5日、勝率65〜72%。**初期の主軸** |
| 2 | A / B | 順張り（例: 5日で+1.5σブレイク） | 日足検証でA区分+63bp/5日。コスト控除後の優位性が未確認のため**検証後・小ロットで開始** |
| — | D | 停止 | サンプル不足。長期データで確認するまで例外なし |

### 4.3 ポジションサイズ
- ボラ・ターゲティング: ロット係数 = 目標ボラ ÷ 現在の $\sigma_{YZ}$（上限キャップつき）。
- 1トレードの許容損失 = 口座リスク資本の0.5〜1%。ロット = 許容損失 ÷ (損切り幅 + 想定ギャップ幅)。想定ギャップは過去最悪級の1日下落（2024/8/5の日経−12%相当）を含めて決める。
- 維持率が警戒水準を割ったら、ロット係数と損切り幅を自動で絞る。

### 4.4 出口（4層ストップ）
| 層 | 条件 | 処理 | 決め方 |
|---|---|---|---|
| ① 価格 | エントリー時に固定した損切り価格（$k\times$ATR） | 即決済。後から広げない | 勝ちトレードのMAE分布から、勝ちの大半を切らない位置 |
| ② 時間 | N日経過しても含み益にならない | 決済 | 勝ちトレードが利益圏に入る日数の80パーセンタイル |
| ③ レジーム遷移 | 保有中に区分が変わる | 下表の既定ルール | 遷移頻度（平均継続24〜31日）が保有期間と同程度のため必須 |
| ④ 口座 | スイング枠DD、連敗数、維持率 | 新規停止→縮小→全決済 | 戦略そのものを止める装置。最適化対象外 |

①と④の閾値は**最適化の対象から外し**、リスク許容度から固定値で決める（最適化すると「損切りしない方がよい」という過学習結果になりやすい）。トレーリングは順張りポジションにのみ任意で併用する。

**遷移時の既定ルール**
| 遷移 | 順張りポジション | 逆張りポジション |
|---|---|---|
| A/B → C | 翌寄りで全決済 | 継続（ストップ据え置き） |
| A/B/C → D | 翌寄りで全決済 | 翌寄りで全決済 |
| C → B/A | — | 継続（目標または時間ストップまで） |
| B → A | 継続、ロット追加なし | 継続、新規なし |

### 4.5 執行
- エントリーは翌営業日の寄付成行または当日引け成行。検証では**翌日寄り約定**を前提にし、当日終値約定（先読み）は使わない。
- 寄付のギャップが想定を超えた場合（例: 損切り幅の50%以上の不利なギャップ）はエントリーを見送る。

## 5. 階層③：デイトレード（`day` / 1570）

### 5.1 時間軸ごとの市場特性（設計の前提、フェーズ2で実測）
| 時間軸 | 支配的な性質 | 原因 | 設計への含意 |
|---|---|---|---|
| ティック〜数分 | 平均回帰（負の自己相関） | Bid-Askバウンス、マーケットメイカーの在庫調整 | **成行で飛びつかない**。受動指値で入る。ただしこれは「必ず押し目が来る」ことを意味しない |
| 15分〜1日 | 弱いモメンタム | 夜間情報の消化、機関のVWAP/TWAP執行 | 寄り後30分の方向が引け前30分の方向を予測する（Gao et al. 2018はS&P500 ETFでの結果。日本市場・1570での再現はフェーズ2で確認） |
| 数日〜数週 | 短期リバーサル | パニック後の自律反発 | 日足検証の逆張り優位と整合 |

### 5.2 共通ルール
- 1戦略につき1日1回、1方向のみ。両戦略が同日に同方向で成立した場合は合算建玉をデイトレ枠上限内に抑える。
- **日次損失上限**: デイトレ枠の当日損失が上限に達したら当日は全停止。
- 15:24までに全決済（§8.3）。
- ギャップ・レンジ等の判定は**先物または1321**で行い、1570は執行対象としてのみ扱う（1570は2倍レバレッジのため閾値が歪む）。
- ナイトセッション終値を用いて**寄り前に当日の予想ギャップを算出**し、戦略1の事前準備（監視モード）を行う。これはリアルタイム配信とは独立に得られる情報優位である。

### 5.3 戦略1：寄り付きギャップ逆張り（レジームB / C）
- **根拠**: 夜間の海外市場急落によるオーバーシュートからの自律反発。日足検証「荒れた局面で逆張りが効く」と整合。
- **対象日**: 日経（先物/1321）が前日終値から $0.5\sim0.8\,\sigma_{YZ}$ 以上ギャップダウンして寄った日。
- **除外**: ギャップが $2\sigma_{YZ}$ を超える日（暴落日は反発しない。2024/8/5型）、先物が夜間にサーキットブレーカーに達した日、当日に重要イベント（日銀会合・FOMC翌日等）があるとLLMフラグが立った日はロット半減または停止。
- **エントリー**: 寄り直後の投げを見送り、下げ止まり（5〜15分足の陽線確定または安値維持）を確認して受動指値でロング。指値は有効期限（例: 15分）を持ち、安値更新で取り消す。
- **出口**: 当日VWAP到達またはギャップ半値戻しで利確。寄り安値割れで損切り。未達なら前引けまたは15:24で決済。

### 5.4 戦略2：初動モメンタム順張り × 押し目受動指値（レジームA / B）
- **根拠**: 寄り後30分のモメンタム持続と、「高値圏のブレイク掴み」「成行スリッページ」の構造的排除。
- **初動判定（9:00〜9:30）**: 9:30時点で始値からのリターンが閾値以上、VWAPより上、先物も同方向。ただし最初の30分で日次ATRの一定割合（フェーズ2で決定）以上を消費した日は除外（伸びすぎ）。
- **エントリー（9:30〜11:00、1日1回）**: 高値ブレイクを買わず、最初の押し目（VWAP付近または9:00〜9:30レンジの半値押し）に買い受動指値を置く。
- **逆選択対策**: 押し目指値は「約定する時はトレンドが終わっている」リスクを持つ。指値の有効期限（例: 30分）、VWAPを一定幅割ったら取り消し、約定率と約定後リターンをログで計測し、不利なら指値位置を浅くする。
- **後半エントリー禁止**: 11:00以降は新規なし。
- **出口**: 寄り安値割れ等の構造的損切りに掛からなければ、**15:00〜15:20の間に時間決済**（15:24ハードリミット）。場中の浅いトレーリングは日中の自然な戻しで狩られるため行わない。1570のリバランス売買が入る引け間際は先物との乖離が大きくなるため、引け成行に依存しない。
- **下落日の扱い**: 1570のショートは貸株料・逆日歩・貸借停止のリスクがある。下落モメンタムを取る場合は1357（ダブルインバース）のロングを候補とし、流動性とコストを比較して決める。初期はロングのみ。

### 5.5 リアルタイム配信の役割
PUSH配信はHFTと速さを競うためではなく、**守りと計測**に使う。
1. 執行品質: 板を見て受動指値で入り、スリッページを抑える。約定率・実効スプレッドを毎日集計。
2. リスク管理: 15:24全決済、損切りの即時執行、異常値動き時のサーキットブレーカー（§8.4）。
3. ログ蓄積: 先物・1321・1570の分足・歩み値・板スナップショットを `rr` に保存し、フェーズ2の計測とメタラベリングの基盤にする。

## 6. 検証方針と採否基準

### 6.1 現行検証（2010〜2026、ETF3銘柄）に対する懸念
1. **C区分の年率69〜70%は過大評価**。独立エピソードは実質3〜5件で、いずれもV字回復。2000〜2002年・2008年の長期C局面を含めると大きく低下する可能性が高い。
2. **「200日線割れで降りる vs 買い持ち」の比較が不公平**。信用ロングには金利・担保評価減のコストがあり、「降りる価値」が過小評価されている。
3. **逆張り検証が執行・コスト・MAEを無視**。約定タイミング（当日終値は先読み）、往復コスト、保有中の最大含み損を出す必要がある。A区分の+17bpはコスト控除後に消える。
4. **3銘柄が独立でない**。暴落時の相関は1に近い。円建てETFには為替が混入する。
5. **3年ボラ順位が2024〜2025年で歪む**（§3.2-3で対策）。
6. **D区分のサンプル不足**。「D＝停止」を既定とする。
7. **レジーム継続期間とスイング保有期間の重複**（§4.4で対策）。

### 6.2 採否基準（事前登録）
結果を見てから採用を決めることを防ぐため、検証前に合否基準を固定する。

| 検証項目 | 合格条件 |
|---|---|
| C区分の逆張り（2000年以降、原指数、翌日寄り約定、コスト控除後） | 期待値プラス、独立エピソード10件以上、2000〜2009年のサブ期間でも致命的でない（最大DDがリスク予算内） |
| A区分の順張りスイング | コスト2倍でも期待値プラス。満たさなければ順張りスイングは採用しない |
| D区分 | 長期データで明確な優位性がない限り停止を維持 |
| レジーム切替頻度 | 4区分で年8〜10回以下を維持。ボラ軸ヒステリシス導入後に再計測 |
| デイトレ戦略1・2 | フェーズ2の実測で前提（§5.1）が成立し、ペーパートレード3ヶ月でコスト控除後プラス |

### 6.3 パラメータ更新の規律
- 階層固定型（シーケンシャル）最適化: ①を固定して②を、①②を所与として③を訓練する。
- 更新頻度: スイングは月次、デイトレは週次〜月次。**更新しても成績が有意に改善しない場合は更新しない**（ヒステリシス）。
- 最適解ではなく近傍の平均（プラトー）を採用し、前回値との加重平均で慣性を持たせる。
- 短期窓の目的関数にカルマーレシオ単独は使わない（最大DDが不安定）。コスト控除後Profit Factorや取引回数ペナルティ付きSharpeを併用する。
- 損切り（§4.4①④）、日次損失上限、レバレッジ上限は最適化対象外。

## 8. 運用・フェイルセーフ

### 8.1 再起動と起動確認
- 再起動は06:30（先物ナイトセッション終了後、`ksm`起動前）。場中・ナイトセッション中の再起動は禁止。
- `ksm` の起動・ログイン・API疎通のいずれかが失敗した場合は通知し、**当日はスイングの新規・デイトレを全停止**（既存スイング玉の損切りは手動対応へ切り替え）。

### 8.2 バッチ失敗時
- `collect` / `process` / `regime` の連鎖が失敗・遅延した場合、**前日コンフィグでの取引継続はせず、当日は新規停止**（フェイルセーフ）。
- 先物データが途絶した場合、`day` は新規を停止し、既存建玉の損切り監視と15:24決済のみ継続。

### 8.3 15:24全決済の確実性
- 15:20から決済処理を開始し、未約定があれば15:22、15:24に成行で再送。
- 15:24を過ぎて残玉がある場合は即時通知し、15:25〜15:30のクロージング・オークションで決済を試みる。翌日持ち越しとなった場合は、翌寄りで決済し、日計り優遇の不適用コストを記録する。

### 8.4 サーキットブレーカー
- 定量定義: 先物の5分リターンが日次 $\sigma_{YZ}$ の一定倍を超えた場合、または先物の取引所CB発動時。
- 動作: 新規停止、既存デイトレ玉は損切り幅を縮小、スイング玉は維持率トリガーに従う。

### 8.5 監視・照合・キルスイッチ
- 死活監視: `day` のハートビートが途切れたら通知。
- 日次照合（`reconcile`）: 証券会社の建玉・残高・維持率とDBの不一致は翌日の取引を停止する。
- キルスイッチ: 全戦略の即時停止と全決済を1コマンドで実行できること。手動・遠隔から起動可能にする。
- 通知: 失敗・異常・トリガー発動はすべて即時通知（LINE/Slack等）。

### 8.6 変更管理
- パラメータ変更・コード変更は `rr` のパラメータ履歴テーブルに記録し、約定ログと紐づける。
- 本番投入は開発PCでのバックテスト・ペーパー結果を添えてリリース制御テーブルに登録したものだけを許可する。
