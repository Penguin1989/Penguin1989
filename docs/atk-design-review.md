# ggs-atk（atk）設計レビュー：懸念点・リスク／推進すべき点・評価できる点

対象文書: 「代用有価証券を活用した信用システムトレード 総合設計書」
レビュー日: 2026-10-14

本レビューは設計書の記述のみを前提に、(1) 懸念点・リスク、(2) 推進すべき点・評価できる点、(3) 優先アクション、の順に整理する。
数値や制度上の前提（代用掛目、日計り信用の条件、ETFの信用取引区分など）は証券会社・取引所の最新規約で必ず再確認すること。

| 観点 | 評価 | 一言 |

| アーキテクチャ（3階層・疎結合） | ○ | 構造は良い。ただし階層間の「結合点」（担保・資金）の設計が薄い |

## 1. 懸念点・リスク

### 1.1 【最重要】担保資産と建玉の相関リスク（ポータブル・アルファの前提崩れ）

- **問題**: 担保が「海外株式インデックスETF」、建玉が「日経（1570／スイング）」。平時の相関は中程度でも、**リスクオフ局面では世界株と日経が同時に急落**し、以下が同時に発生する。
  1. 担保評価額の低下（代用掛目は通常80%前後、さらに証券会社が急落時に掛目を引き下げる可能性）
  2. 建玉（特にロング）の評価損拡大
  3. 為替（円高）による海外株ETFの円建て下落 ← 日経急落と円高は同時に起きやすい
- **結果**: 保証金維持率が想定より速く低下し、**追証→担保ETFの強制決済**という「コア資産を失う」最悪ケースにつながる。これはポータブル・アルファ戦略の前提そのものを破壊する。
- **設計書の弱点**: 「スイング枠は実質保証金の0.5〜0.7倍」「現金バッファ15〜20%」は定性的な目安であり、**ストレス下での維持率シミュレーション**が示されていない。
- **推奨**:
  - 2008年9〜10月、2011年3月、2015年8月、2018年2月、2020年3月、2024年8月5日などの急落日について「担保評価額×掛目 − 建玉評価損 − 金利・諸費用」で**維持率の日次推移を再現**し、最低維持率に対して十分な余裕があることを確認する。
  - 「担保の掛目引き下げ」「為替急変」を変数として含めたストレステスト。
  - **建玉上限は『保証金』ではなく『ストレス後の担保評価額』基準**で決める。
  - デイトレ・スイング合計の建玉上限（合算レバレッジ上限）を明文化する。現状は階層ごとに独立しているため、合算で過大になる余地がある。

### 1.2 1570（日経レバETF）固有のリスク

- **減価（ボラティリティ・ドラッグ）**: 日次リバランス型レバETFは、横ばい・高ボラ時に対象指数より減価する。デイトレ（当日決済）なら影響は小さいが、**スイング枠で1570を使うなら要注意**。設計書ではスイングの対象銘柄が明記されていないので、1570をスイングで使わない方針を明文化すべき。
- **先物との乖離**: 1570は引け間際にリバランス売買が入り、15:00〜15:30（クロージング・オークション付近）は先物との連動が崩れやすい。**15:24の完全クローズが、まさに乖離が大きくなる時間帯に当たる**点に注意。
  - 対策: クローズ時刻を前倒し（15:10〜15:15）する選択肢、あるいは引けのオークションを使う／使わないを検証で決める。
- **信用取引の売り（ショート）**: 1570は制度信用の売建てが可能だが、逆日歩・貸株料や貸借の停止リスクがある。レジームC/Dでのショート戦略はこれを考慮したコストモデルが必須。
- **流動性**: 通常は十分だが、1570の板は先物より薄い。ADVの1/50という出来高バーの閾値も、**年間を通じてバー本数が大きく変動**するため、ADVの再計算頻度とバー本数の下限/上限を決める必要がある。

### 1.3 コストが戦略の期待値を食いつぶすリスク

- デイトレの順張りブレイクアウトは、**1回あたりの期待利益が小さく、スプレッド＋スリッページ＋日計り金利の合計に敏感**。
- 設計書には取引コストモデルの記述がない。バックテストでは最低限、
  - スプレッド（1570の呼値1円。価格帯により往復で0.005〜0.01%程度）
  - 成行時のスリッページ（ブレイクアウトは**不利な方向に滑りやすい**）
  - 日計り信用の金利・手数料（優遇の条件と、適用外になる場合の通常金利）
  - 信用売りの貸株料・逆日歩
  - 15:24強制決済時のインパクト
  を保守的に織り込むこと。**コストを2倍にしても黒字かどうか**をロバスト性の基準にすることを推奨する。

### 1.4 スイング階層の設計が薄い

- 設計書内で最も記述が少ない。現状分かるのは「レジームに応じて閾値・保有期間を切り替える」「建玉上限0.5〜0.7倍」のみ。
- 未定義の要素:
  - 1ポジションあたりの損切り（ATR基準か固定%か）
  - 同時保有ポジション数、銘柄（1321？1570？個別？）
  - ギャップリスク（オーバーナイトで損切り幅を超える窓）への対処
  - レジームがA→Cに遷移したとき、既存ポジションをどう扱うか（即時クローズか、ルール据え置きか）
  - 決算・FOMC・日銀会合など**既知イベントをまたぐかどうか**のルール
- オーバーナイトを持つ以上、**夜間リスクの実質的な担い手はこの階層**。デイトレより先にここを固めるべき。

### 1.5 「予測しない」と「月次／週次の再最適化」の内在的な緊張

- 直近データでパラメータを頻繁に再最適化することは、**「直近の市場構造が続く」という暗黙の予測**である。これ自体は悪くないが、設計思想の「予測しない」とは整合的に言語化しておくべき。
- 過学習リスク:
  - 階層③の自由パラメータが多い（ER閾値、バー閾値、ATR係数m、過熱検知の閾値群、リード確認の条件…）。週次の窓（例: 直近4〜8週）で最適化すると、**サンプル数に対してパラメータが多すぎる**可能性が高い。
  - 対策: (a) パラメータの探索範囲を狭く固定し「微調整」に限定する、(b) 最適解ではなく**近傍の平均（プラトー）**を採用する、(c) パラメータ更新に慣性（前回値との加重平均）を入れる、(d) 更新しても成績が有意に改善しないなら更新しない、という**ヒステリシス**を設ける。
- カルマーレシオは分母が最大DDであり、**短期窓では極めて不安定**。週次最適化の目的関数には、より分散の小さい指標（例: コスト控除後のProfit Factor、取引回数ペナルティ付きSharpe）を併用すること。

### 1.6 レジーム判定の境界問題

- 200日MAの±2%帯、ボラ上位20%、いずれも「境界付近で頻繫に反転」しやすい。帯で抑制しているのは良いが、**レジーム遷移時にスイングのパラメータが切り替わる→既存ポジションの整合性が崩れる**問題が残る。
- 「過去3年の上位20%」はルックバックに依存し、**低ボラ期間が3年続いた後の小さな上昇も『荒れ』と判定**される。絶対値の下限（例: 年率ボラ○%以上）を併用することを推奨。
- 4区分の期待値コメント（例: 「Cは逆張りの期待値が極めて高い」）は仮説であり、**サンプル数が少ない区分（Cは出現頻度が低い）で過信しない**こと。区分ごとの取引数と信頼区間をレポートに出すべき。

### 1.7 運用・実装リスク

- **タイミング依存のバッチ連鎖**（8:00→8:15→8:30）: 一つが失敗・遅延した場合のフォールバック（前日コンフィグ継続か、取引停止か）を明文化。デフォルトは「取引停止（フェイルセーフ）」を推奨。
- **データ品質**: 先物の出来高データの遅延・欠損はボリューム・クロックの全体を止める。先物データ断で1570のみ生きている場合の挙動を決めておく。
- **15:24クローズの確実性**: API障害・発注拒否時のリトライとエスカレーション（手動通知）を設計。「残玉が翌日に持ち越される」は日計り信用の優遇条件を失うだけでなく、意図しない夜間リスクになる。
- **ブラックリスト**: 担保ETFの誤売却防止は良いが、「ハードコーディング」では銘柄入れ替え時にデプロイが必要。コードレベルの保護＋設定レベルの二重化が望ましい。
- **サーキットブレーカーの基準**: 「ボラ急騰時」の定義（何を、どの時間軸で、どの閾値で）を明示。取引所のサーキットブレーカー（先物）発動時の挙動も規定する。

### 1.8 ML／LLM 部分のリスク

- **LightGBMメタラベリング**: 板情報（厚み・流速）はバックテスト用に**過去の板データを保存していないと学習できない**。実データの蓄積を始めてから数ヶ月は学習不可。優先度は低く、まず「ルールベースで黒字」を確認してからで良い。
- **LLMによるリスクフラグ**: 出力が非決定的で、同じニュースでも日によって判断が変わり得る。発注に直結させるのではなく、**「人間が確認する警告」または「ロット係数の上限を下げるだけ」**に用途を限定する方が安全。
- **LLM監査レポート**: 有用だが、LLMがもっともらしい敗因を「作る」リスクがある。数値根拠（取引ログの集計）を同時に出し、LLMは解釈のみ担当させる。

### 1.9 法規制・口座面の確認事項

- 自動売買の利用規約（証券会社ごとのAPI利用条件、発注頻度制限）。
- 日計り信用の優遇条件（銘柄、約定金額、決済時刻）と、**条件を満たさなかった場合のペナルティ**。
- 代用有価証券の掛目と、証券会社が**任意に掛目を変更できる条項**。
- 信用取引と税務（ETF配当・分配金の扱い、損益通算）。

## 2. 推進すべき点・評価できる点

### 2.1 基本思想

- **ポータブル・アルファ**: 遊休担保力の活用という発想は合理的。コア資産を売らずに流動性を得られる点は、課税の繰延（含み益を実現させない）という副次効果もある。
- **「予測しない」適応型制御**: 価格予測モデルより、ルールの適応的チューニングの方が再現性・説明可能性が高く、個人運用に適している。思想として一貫している。
- **疎結合3階層**: 時間軸ごとに責務を分けており、どこが機能していないかの切り分けが容易。障害時に階層単位で停止できる点も良い。

### 2.2 レジーム判定（階層①）

- 200日MA＋ボラという**少パラメータ・高解釈性**の構成は、長期的に壊れにくい。
- ±2%の帯によるヒステリシス、四半期〜半年の見直しサイクルなど、**「頻繁に触らない」姿勢**が正しい。
- 1321を判定基準にして1570で執行する分離も、レバETFの減価ノイズを判定から排除できるので妥当。

### 2.3 デイトレ階層（階層③）の設計品質

- **クロスアセット・ボリューム・クロック**: 先物出来高で1570のバーを刻む発想は、情報の震源地にクロックを合わせる点で理論的に筋が良い。閑散時のノイズ除去にも効く。
- **ER（効率比）フィルター**: ブレイクアウト戦略の最大の弱点「ダマシ」を、追加データなしで減らす手段として適切。
- **先物・現物のリード確認**: 複数アセットの合意を取る発想は、1570単独のノイズに対する良い防御。
- **アダプティブ・トレーリング（シャンデリア＋過熱検知）**: 利確の固定幅を避け、ボラに応じて調整するのは合理的。
- **15:24完全クローズ**: 夜間リスクをデイトレ枠から排除し、リスクの所在をスイング枠に一本化する考え方は明快。

### 2.4 最適化・検証プロセス

- **階層固定型（シーケンシャル）最適化**: 組み合わせ爆発を避ける実務的な手法で、評価できる。
- **ウォークフォワード／ローリング検証**: インサンプルの成績を鵜呑みにしない姿勢が設計に組み込まれている。
- **リスク調整後リターンを目的関数にする**: 単純な累積リターン最大化より健全。

### 2.5 リスク管理

- 現金バッファ、日計りクローズ、ブラックリスト、サーキットブレーカーと、**異なる層の安全装置を重ねている**のは良い。
- 「担保ETFの誤売却防止」をコードレベルで持つ発想は、自動売買で最もありがちな致命的事故への対処として正しい。

### 2.6 ML／LLM の「使い所」の選定

- 価格予測にMLを使わず、**メタラベリング（既存シグナルのフィルタ）**と**非構造化情報の構造化（LLM）**に限定しているのは、現実的で成功確率の高い使い方。

## 3. 推奨する優先アクション（実装順）

| 優先 | アクション | 理由 |
|---|---|---|
| 1 | **担保連動ストレステスト**（1.1）: 過去急落局面での維持率再現、合算レバレッジ上限の明文化 | 戦略の成立条件そのもの。ここが成立しないなら他の全てが無意味 |
| 2 | **コストモデルの確定**（1.3）: スプレッド・スリッページ・金利・貸株料を保守的に設定 | 期待値の有無を判断する前提 |
| 3 | **階層①＋階層②の最小実装とバックテスト**（1.4, 1.6） | 夜間リスクの担い手を先に固める。日足のみでデータ要件が軽い |
| 4 | **階層③のルール版バックテスト**（ML無し） | ボリューム・クロック＋ER＋シャンデリアだけでコスト控除後に黒字かを確認 |
| 5 | **運用フェイルセーフ**（1.7）: バッチ失敗時の停止、15:24クローズのリトライ、監視・通知 | 本番前に必須 |
| 6 | **ペーパートレード→小ロット実弾**（例: 想定ロットの10%で1〜3ヶ月） | バックテストと実約定の差（スリッページ・約定率）を実測 |
| 7 | 板データの蓄積開始 → LightGBMメタラベリング（1.8） | データが貯まるまで学習不可。早期に蓄積だけ始める |
| 8 | LLMによる監査レポート・リスクフラグ（警告用途に限定） | 運用が安定してから付加価値として |

- [ ] レジーム判定のボラ絶対下限
- [ ] バッチ失敗時のフォールバック方針（デフォルト停止）
- [ ] 15:24クローズ失敗時の手順（リトライ回数、人間への通知、翌日の対処）
- [ ] サーキットブレーカーの定量定義と、取引所CB発動時の挙動
- [ ] LLM出力の用途制限（発注に直結させない）
- [ ] 証券会社の規約確認結果（API、日計り優遇条件、掛目変更条項）

## 5. まとめ

atkは「担保の遊休購買力から、解釈可能な適応ルールでアルファを取る」という明確な軸を持ち、階層分離・ウォークフォワード・多層の安全装置など、設計の骨格はしっかりしている。
一方で、戦略の成否を最終的に決めるのは**担保資産と建玉の同時下落に耐えられるか**であり、この一点は設計書内でまだ定量化されていない。ここを最初に埋め、次にスイング階層のリスク規律とコストモデルを固めれば、残りの要素（ボリューム・クロック、ML、LLM）は段階的に積み上げていける構成になっている。
